# GME Test Agent 后端功能说明

> 用途：汇报与评审。说明后端"能做什么、怎么运转、可信在哪"；实现细节见《后端总览》（`docs/backend-overview.md`）。

## 一、定位

GME Test Agent 是一个**本地测试工作流服务**：围绕 GME 接口，自动生成"GME 与 ACIS 对同一输入的对比测试"，并对每一步做机器校验，最终把通过的用例或发现的分歧以 PR 形式交付。它不替代人写测试，而是把"选接口 → 写用例 → 构建 → 跑测 → 审失败 → 交付"整条链路自动化，并把每个环节的证据留下来。

## 二、核心功能

**1. 接口选择与任务创建**
按模块浏览接口目录（base / kernel / laws），可按接口清单、自由文本目标或整模块批量创建生成任务；也支持在既有任务上继续补充用例、或对失败任务重试。

**2. 自动化测试生成**
每个任务在独立的代码工作树中运行，由一个**隔离沙箱里的编码会话**（只允许改测试仓库、不允许交互确认）完成分析与写用例。任务可跨进程恢复；编码会话的每一步工具调用都记录在任务日志里，可事后审计。

**3. 权威校验（AI 的自述不算数）**
生成的代码必须通过后端自己执行的检查才算数：改动范围（只许改测试仓库）、用例清单合法性（必须插入既有测试文件）、九个维度的覆盖率完整性、构建、按精确过滤条件运行全部新增用例、以及逐条用例的**内存审计**（零泄漏、零错误释放）与代码格式检查。任何一项不过，任务停在该步并保留现场。

**4. 失败即产出（分歧管理）**
对比断言失败被视为**发现了一条 GME 与 ACIS 的真实行为分歧**，而不是缺陷：失败被完整记录（属于哪个接口、断言差异原文、复现命令、每次运行的观测），跨运行稳定复现的分歧会自动"升格"为先验知识，供后续任务生成更有针对性的用例。

**5. 知识注入与闭环**
生成任务开始前，后端会自动把两类知识注入给编码会话：**本地历史分歧**（按接口 / API / 模块三级匹配）和**知识库参照**（逐库检索、各自独立超时与降级），并按优先级与字数预算裁剪、标注来源。注入的原文、命中情况、耗时、是否降级全部落盘留痕。该能力默认关闭，开启后也不影响任务成功率（任何检索失败只降级、不阻断）。

**6. 交付**
三条 PR 路径按需选择：**证据 PR**（保留真实失败红灯，交付分歧证据）、**绿灯 PR**（对已知失败打跳过标记）、**精选用例 PR**（只交付选中的测试）。另配套**源码缺陷修复流程**：对确认的 GME 缺陷自动修源码，要求测试全绿 + 内存审计通过后才允许提交。

## 三、一条任务的典型流程

```
创建任务 → 准备独立工作树 → （注入知识）→ 编码会话生成用例
        → 构建 → 运行新增用例 → [有失败? 可选跳过重跑]
        → 待人工审阅 → 选择 PR 路径 → 交付
```

每步的状态、日志、提示词原文、测试结果与代码差异都保存在任务工件目录中，供事后审阅与追责。

## 四、可信性设计

- **职责隔离**：AI 只负责写代码；构建、测试、审计、交付全部由后端权威执行与复核。
- **单一事实源**：所有任务状态持久化在本地数据库，服务重启不丢、可续。
- **全程留痕**：给模型的完整提示词、模型产出、注入内容、每条用例结果、净差异逐一落盘。
- **硬性并发控制**：生成与重试有并发上限，同一任务同时只允许一个动作，防止互相踩踏。

## 五、运行形态与依赖

三种使用形态：源码运行（开发）、本地 Web 界面、打包桌面版。依赖：Python 3.10+、DeepSeek Harness SDK、GME 源码与 CMake/MSVC 工具链、GitHub CLI（PR 交付用）。

## 六、近期增强（本轮合入）

**知识注入与轨迹可观测**：生成前确定性注入历史分歧与知识库参照（来源标签、优先级、字数预算、逐级降级），失败按判据自动升格为先验形成闭环；内层会话的工具调用以事件形式落库。配套 216 项自动化检查全部通过，对既有行为零影响（默认关闭、开启后不改变任何"什么算通过"的判定）。
